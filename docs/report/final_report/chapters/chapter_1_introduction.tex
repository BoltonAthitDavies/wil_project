\section{Background and Significance}
\label{sec:background}

Autonomous mobile robots (AMRs) play a central role in raising the efficiency of
warehouse logistics. Gensurv Robotics currently relies on 2-D LiDAR sensing
combined with QR-code navigation. That solution carries business limitations:
LiDAR sensors are expensive, and the approach is inflexible because the company
must spend money and time modifying the warehouse infrastructure to install
artificial reference markers. Moving from LiDAR to vision-based navigation,
which uses lower-cost camera sensors and yields richer information about the
environment, is therefore an option that directly addresses the company's cost
problem.

Bringing cameras and simultaneous localization and mapping from images (visual
SLAM) into real warehouse use nevertheless raises a substantial academic
challenge. Most standard visual SLAM algorithms were developed under the
assumption that the environment is static. Saputra et al.~\cite{saputra2018}
state clearly that when a SLAM system is deployed in a dynamic environment, such
as a warehouse in which goods and obstacles are continually moved, its accuracy
degrades severely, because the system draws features from moving objects into
its pose computation. Cadena et al.~\cite{cadena2016} further stress that the
greatest challenges facing SLAM today are robustness and lifelong mapping: the
robot must be able to separate permanent structure from dynamic objects.

To address localization in a dynamic environment without floor
infrastructure, this project builds a localization and mapping pipeline that
uses only stereo cameras and an inertial measurement unit, and measures how
well it works. Two stereo-inertial front ends, ORB-SLAM3 and VINS-Fusion, are
compared against each other and against estimators that use no camera at all;
RTAB-Map serves as the back end that builds a prior map and relocalizes the
robot in it; and the result is delivered in the form the Nav2 navigation stack
consumes. Each part is evaluated in a Gazebo simulation of a warehouse, with
and without moving traffic, and on the real robot.

Replacing an active sensor (LiDAR) with a passive one (a camera) may also make
the system sensitive to indoor lighting. The original plan designed an
experiment around scheduled light changes; that experiment was not carried out
within the reporting period, and the change is recorded with the other
deviations from the proposal in \cref{sec:deviations}.

\section{Objectives}
\label{sec:objectives}

\begin{enumerate}[leftmargin=2em]
  \item Build a localization and mapping pipeline that uses only cameras and an
    IMU for a warehouse AMR, with no floor markers. It has three parts:
    \begin{enumerate}[label=(\alph*)]
      \item two stereo-inertial front ends, ORB-SLAM3 and VINS-Fusion;
      \item RTAB-Map as the back end, which builds a prior map and relocalizes
        the robot in it;
      \item outputs in the form Nav2 consumes, the
        \texttt{map}~$\rightarrow$~\texttt{odom} transform and the
        \texttt{/map} occupancy grid.
    \end{enumerate}
  \item Run the pipeline both in a Gazebo warehouse and on the real robot.
  \item Evaluate localization accuracy: compare the estimated pose of each front
    end with ground truth, in static warehouses and in warehouses with moving
    traffic, and compare it against estimators that use no camera (wheel, IMU
    and an extended Kalman filter in simulation; wheel plus gyroscope on the
    robot).
  \item Evaluate the prior map RTAB-Map builds in two ways:
    \begin{enumerate}[label=(\alph*)]
      \item the pose graph, by comparing the node poses with the ground truth of
        the mapping run;
      \item the occupancy grid, by comparing it with the true warehouse geometry,
        both for geometry and for false obstacles.
    \end{enumerate}
  \item Evaluate relocalization in the prior map: compare the localized pose
    with ground truth while the robot drives through a mapped warehouse.
\end{enumerate}

These objectives replace the five of the original proposal, which included
low-light image enhancement, deep-learning detection and masking of dynamic
objects, and lane detection with lane tracking. \Cref{sec:deviations} records
each change and the reason for it.

\section{Expected Benefits}
\label{sec:benefits}

\begin{enumerate}[leftmargin=2em]
  \item Help the company reduce the cost of modifying warehouse infrastructure
    for AMR navigation.
  \item Obtain a navigation pipeline that is robust to a dynamic environment.
  \item Allow the pipeline to be plugged into the control and motion-planning
    systems for real use on warehouse robots.
\end{enumerate}

\section{Scope}
\label{sec:scope}

\begin{enumerate}[leftmargin=2em]
  \item \textbf{Simulation:}
    \begin{enumerate}[label=(\alph*)]
      \item the realistic Gazebo warehouse in two layouts, U and I;
      \item four localization recordings, a static and a moving-traffic one per
        layout (\repo{realistic_000} to \repo{realistic_003});
      \item two long mapping recordings, from which the prior maps are built, and
        the small tiny-warehouse map;
      \item six relocalization runs on the prior maps.
    \end{enumerate}
  \item \textbf{Real robot:} an Ackermann platform with AC-IMX390-H190 fisheye
    stereo cameras ($1920\times1080$) and a \SI{200}{\hertz} IMU, recorded at the
    Gensurv building. Four recordings carry tracker ground truth; three of them
    pass the validity rules of \cref{sec:method-trajectory}, and the fourth is reported
    as a diagnostic.
  \item \textbf{Software}, developed in ROS~2 Humble:
    \begin{enumerate}[label=(\alph*)]
      \item ORB-SLAM3 from the project's fork (patches up to 15, optional GPU front
        end);
      \item VINS-Fusion from the project's fork (no loop fusion);
      \item RTAB-Map 0.23 with the project's camera shim, correction gate and start
        delay.
    \end{enumerate}
  \item \textbf{Computing:} every run in this report, in both domains, executes on
    one development laptop, an MSI Katana GF66 11UG. The NRU-51V on the robot
    records the data and runs no estimator.
  \item \textbf{Evaluation:} localization and mapping replay recorded bags at rate
    1.0. Relocalization runs live in simulation, with the robot driven by hand
    along its routes.
  \item \textbf{Excluded:} path planning and motion control. The pipeline
    delivers a pose and a map to Nav2, which is the consumer, not the subject,
    of this project.
\end{enumerate}
